# Env for hf_adapter_new2 (museglimmer_poc base)

The shared conda env `torchtitan_py312` is one release behind this base and is
shared with other branches (scan_poc pins spmd_types 0.2.1), so the four
newer deps live in a side directory instead of being installed into it:

    /mnt/disks/persist/torch-tpu/.pyenvs/spmd025
      spmd_types 0.2.5   (env has 0.2.1 -- do NOT upgrade in place)
      grain 0.2.18
      attn-gym 0.0.8
      torch_remat @ d302699b

Run with:
    PYTHONPATH=/mnt/disks/persist/torch-tpu/.pyenvs/spmd025:<worktree>

Import torch_tpu before spmd_types: spmd_types imports torch, torch's
device-backend autoload pulls in torch_tpu, and torch_tpu reaches back into
spmd_types -- importing spmd_types first deadlocks that cycle and surfaces as
"Failed to load the backend extension: torch_tpu". Entry points that import
torch_tpu early (torchtitan.experiments.tpu.train) are unaffected.

transformers: this base pins 5.10.1 and works on the env's 5.15.0. The 4.57.1
shim at .pyenvs/tf457 that hf_adapter needs is NOT used here.
